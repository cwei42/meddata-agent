# Changelog

All notable changes are listed here. The project follows [Semantic Versioning](https://semver.org):
MAJOR for incompatible changes to data layout or tools, MINOR for new functions, PATCH for fixes.
Each release is a git tag `vX.Y.Z`; the deployed version and commit are recorded in every result.

## [0.12.2] - 2026-11-27

### Added
- **Operation log per case** (`<case>/journal.jsonl`): every tool call of the agent (also read-only, declined
  and only previewed ones), menu tools, import and export, with version, arguments (names redacted), approval
  and the files created / changed / moved to the bin (size, sha256). New read-only tool `show_journal`.
- **Undo** (console menu 9): undoes the newest step that is not undone yet. Created files go to the bin, a
  replaced result comes back, `work/` is restored. Only the user can undo, the model cannot.
- The log is exported as `JOURNAL.jsonl` next to a result, after the identifier check.

### Changed
- `overwrite=true` no longer deletes the earlier result: it is moved to `<case>/.trash/` (one earlier version
  per step is kept). Before free Python code runs, `work/` is copied so in-place changes can be undone.
- 11 new tests (67).

## [0.12.1] - 2026-11-26

### Added
- **`lookup_uid` tool:** looks up any UID of the DICOM standard offline (pydicom's dictionary, 482 UIDs): SOP
  classes with their category, transfer syntaxes (compressed, lossy), well-known frames of reference. Also
  searches by words. For a SOP class it lists the series of the case that use it.

### Changed
- **Series categories for all storage classes:** the category is derived from the SOP class UID and its standard
  name, so all 207 storage classes get one (before: 28 by hand, the rest `other`). RT treatment records, RT
  second-generation objects and delivery instructions are now `rt`, Key Object Selection is `structured_report`,
  radiopharmaceutical / patient dose SR are `dose_report`. The 28 hand-set entries are kept and win.
- New category `multiframe_image` for Enhanced / Legacy Converted images other than Enhanced CT and MR (e.g.
  Enhanced PET, Legacy Converted CT). They are listed but not exported to MHA until multi-frame export is tested.

## [0.12.0] - 2026-11-26

### Changed
- **Approval only for deleting:** write tools (organize, anonymize, MHA export, structure tools) run without
  asking. A call that deletes or replaces an earlier result (`overwrite=true`) still needs approval, and so does
  free Python code and saving a skill, because the user has to read that code. Policy option `confirm_writes`
  brings back approval for every write
- Console: the approval panel says that the earlier result will be deleted

### Removed
- Web UI (`web/`, `bin/ui-start.sh`, `bin/ui-stop.sh`). The offline console and the command line remain

### Documentation
- README reorganized: quick start first, security and data protection in one section, components next to the
  architecture, a chart of what the model uses of the 8 GB memory, contributions welcome, contact
- Evaluation on 5 public datasets shown per task category (pie charts) with every grade and the reasons for
  partly correct answers in `docs/public-eval.md`, generated by `docs/make_eval_chart.py`

## [0.11.1] - 2026-11-26

Fixes from the 0.11.0 stress and hold-out evaluation.

### Fixed
- **Step limit:** DICOM configs allow 10 model steps and 20 tool calls per question (was 6 / 12); answers were cut
  off before the last tool call. The prompt asks for one call with a pattern instead of one call per structure set
- **Structure classes:** all structure tools accept `select='OARS'` (organs at risk by TG-263 recognition, without
  External, targets and helper structures) and `select='TARGETS'` (GTV / CTV / ITV / PTV); the model invented
  patterns like `OAR*`. "No structure matches" messages point to the two classes
- **"Can you ...?" questions:** recognised in the harness (English, German, Chinese); a write tool then runs only
  as a dry run, without an approval prompt, and the agent describes it and asks. Plain requests still ask for
  approval. Policy option `preview_on_question` (off in the Python config)

### Tests
- 45 automatic tests (was 39); the stress script reads the expected series ids from the tools instead of fixed ids

## [0.11.0] - 2026-11-26

Stress test with a deliberately scrambled copy of the real case (files spread over 30 folders with arbitrary
names, RT objects separated from their images, random file names, files without preamble, duplicates, junk).

### Changed
- **Plans are found from the DICOM content, not from folder names:** RTSTRUCT → its image; images, derived
  images and RTDOSE → the plan whose image has the same origin; RTPLAN → the structure set with the same label;
  plan name from the structure set label (`AKZ01_FX26_ADAPT` → `Fx26`). `list_series` shows `plan=` and filters by
  plan; `structure_set`, `plan_dose` and dose pairing use these plans
- The folder-based guesses of 0.10.0 are removed: with mixed-up folders they linked doses to the wrong plans
- Plan grouping uses UID references first (RTDOSE → RTPLAN → RTSTRUCT); image origin and label only when UIDs
  are broken; a label shared by several structure sets does not name a plan; with several patients the plan
  name carries the patient
- Redaction keeps anatomy / RT words even when they appear in a (test) patient name ("LUNG^TG244")
- `list_series`: `slices=` for images, `1 file` for RT objects, `dose grid N planes` for doses (was `n=1`,
  `1x144fr`, misread as single slices and fractions)
- Prompts and tool descriptions use neutral placeholders instead of example plan names the model copied
- TG-263: site / version suffixes (`_P`, `_old`, `_neu`, `copy`) are ignored and noted

### Added
- Harness guard: an answer that says something was done / exported after only a dry run or a declined write is
  sent back once
- **Thinking mode on** in all configs (Qwen3.5 reasoning, 3000 output tokens); the harness handles its failure
  modes: an empty answer is asked for once, then the end of the reasoning is shown (marked); tool calls written
  as text are recognised and run; a text tool call that can no longer run is removed from the answer
- `check_identifiers` tool: which identifying fields are filled and in how many series (never the values), with a
  verdict (direct identifiers / possibly pseudonyms / none); the prompts no longer claim the data is pseudonymised
- MHA export of a CT with a single slice (SimpleITK fallback where plastimatch fails)

### Hold-out evaluation (public datasets, fixed questions, no tuning on them)
- Before these fixes, 3 public datasets (AAPM TG-244, OnkoDICOM, dicompyler): about 17 of 30 answers acceptable
- After the fixes, 2 datasets never used during development (AAPM TG-236 brachytherapy, pydicom RT test files):
  about 16 of 20; the 3 earlier datasets (now seen): about 27 of 30. Mean time per question about 50 s

### Fixed
- Duplicate files (the same image under another name or folder) made series look like 4D data, so the MHA export
  skipped them; the scan now counts each image once (`duplicates` column in `series.csv`), organize still lists
  the copies
- Flaky anonymization test (an invented replacement name could equal the planted staff name)

## [0.10.0] - 2026-11-25

First run on a real clinical dataset (anonymized adaptive MR-Linac case, German structure names) and a
30-question stress test of the agent.

### Added
- `cli/` folder for all command-line tools (`report`, `organize`, `anonymize`, `to_mha`, `structure_names`,
  `structures`)
- MHA export: choose the reference image per plan by modality (`--ref-modality CT|MR`, agent `reference_modality`)
- Structure tools: `structure_set` filter (`Fx30`, `baseline`, RTSTRUCT id) and `plan_dose`; every result line names
  its structure set and plan
- `list_series`: source folder (plan / fraction), folder summary, RT references (RTSTRUCT → image,
  RTPLAN / RTDOSE → plan and structure set, with folder fallback for broken UID references)
- Write tools: `overwrite=true` replaces an earlier result (approved) instead of failing
- Console test mode (`--test`, menu 8) for anonymized or synthetic data while online, logged
- TG-263: about 60 German synonyms and 14 structures, organ-minus-target (`Lunge-GTV` → `Lungs-GTV`), PRV from
  `Myelon+5mm`, primary / nodal target classifiers, German `H_` helper prefix
- Harness guard: answers with measured values or series ids not looked up in the turn are sent back once
- `CHANGELOG.md`, version in the console header

### Changed
- An RTSTRUCT keeps the image series it names; a reference given for all is only a fallback
- Prompts: structure tools work on the existing export; per-fraction results are never added up
- README rewritten with architecture, data protection and workflow diagrams

### Fixed
- **Session space stayed open** when the console was closed while the model was running (bin scripts had lost
  their executable bit; ending the session now cannot be blocked by stopping the model)
- MHA export failed for RTSTRUCTs with Latin-1 ROI names (German ß)
- Anonymizer invented values for empty attributes (fake clinic name and address)
- Model-copied `[tools used …]` lines listed tools that never ran
- Export identifier check reported success when it had nothing to compare (warns and asks now)
- Offline log entries written before the clock was set are marked
